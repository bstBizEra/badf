# BADF Task Routing

| Intent | Primary references | Required artifact |
| --- | --- | --- |
| Frame new work | `docs/00`, `docs/01`, `docs/13` | Work package |
| Requirement decomposition / G02 (when `badf-requirements` is ACTIVE) | `docs/01`, `docs/05`, `docs/13`, `skills/badf-requirements` | RTM + G02 review evidence |
| Design/build | `docs/02`, `docs/09`, `docs/10` | Session + change evidence |
| Delegate/council | `docs/03`, `docs/06` | Task contract + ballots/handoff |
| Memory/learning | `docs/04`, `docs/12` | Memory or learning record |
| Tool/MCP use | `docs/08`, registries | Tool evidence and returned identity |
| Release/deploy | `docs/11` | Release packet + gate dossier |
| Operate/close | `docs/12` | Runtime evidence + G13/G14 dossier |

Document numbers refer to filenames in repository `docs/`. Always include `docs/05-evidence-and-provenance.md` for a material claim or gate decision.

A registry entry at `IMPLEMENTED`, `VALIDATED`, or `SHADOWED` is not runtime activation. The default policy is approved-only; route production work through a lifecycle skill only after its registry status is `ACTIVE`.
